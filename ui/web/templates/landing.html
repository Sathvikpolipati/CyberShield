Architecture

How CyberShield works

A five-stage pipeline from raw bytes to blocked threats — running live in your network.

1
Stage 1 · Capture
Zero-Driver Packet Capture
The native socket sniffer binds directly to your NIC using Python's raw socket API — zero kernel drivers, zero root requirements on most platforms. Packets are queued at thousands per second.
2
Stage 2 · Parse
Deep Packet Inspection & Protocol Parsing
Each packet is parsed into a typed PacketSummary Pydantic model: source/destination IPs, ports, flags, TTL, DNS queries, HTTP paths, and hex preview — in microseconds.
3
Stage 3 · Analyze
4-Engine Threat Detection Pipeline
The DetectionEngine runs Port Scan, SYN Flood, ICMP Sweep, and DNS Tunnel detectors in parallel. Alerts are generated with severity levels and attacker attribution in real time.
4
Stage 4 · Broadcast
250ms WebSocket Broadcast Cycle
A dedicated asyncio task broadcasts telemetry payloads to all connected SOC dashboard clients every 250ms — stats, new packets, top talkers, alerts, socket table — over live WebSockets.
5
Stage 5 · Mitigate
Automated & Manual IP Firewall Block
Flagged IPs can be auto-blocked via system firewall rules or manually from the dashboard with one click. Blocked IPs are persisted, audited, and can be unblocked at any time.

Everything you need to know about CyberShield SOC.

CyberShield's zero-driver native socket engine works without admin rights on Linux and macOS for basic telemetry. On Windows, some raw socket features require elevation. The web dashboard and REST API always run without elevation. For full packet capture, running with admin/root provides the richest data.
CyberShield SOC is fully tested on Windows 10/11, Ubuntu/Debian Linux, Android Termux (ARM64), and macOS 12+. The web dashboard works on any modern browser. The TUI terminal interface works over SSH on all platforms including headless servers.
CyberShield uses a multi-engine rule-based detection pipeline with statistical anomaly detection. The four built-in detectors use behavioral thresholds (e.g., X SYN packets from the same IP in Y seconds) rather than signature databases, making them effective against zero-day variations. No ML training required.

All data — packets, alerts, device records, and blocked IPs — is stored locally in a SQLite database. CyberShield makes zero outbound connections and never transmits your network data to any external server. It's fully air-gap compatible.
